You are working in the SystemDNA repo. SystemDNA scans a code repository 
into a cross-layer knowledge graph, predicts what one change (for example 
renaming a database column) will break across every layer, and shows 
parallel AI agents fixing each affected part live in a 3D "Agent City". 
Build the frontend's data contracts and mock data in web/ (React 18 + 
Vite + TypeScript strict + vitest, already scaffolded). The backend is 
not ready, so everything must be mockable and must match this spec 
exactly.

B. Impact report (ImpactReport)- Change request: {node, change: "rename", to}. Walking downstream: a 
node that uses the old name directly is "breaking" (keep walking); a node 
that aliases it (cust_id AS customer_key) is "needs_update" (stop; nodes 
using the alias are "safe"); a test or doc mentioning it is "update" 
(stop); a node that only passes data through is "safe" (stop); a medium
confidence (bob) edge gives the same result plus checkThis=true (keep 
walking).- risk 0-100 = 35*fanout + 30*criticality + 20*pii + 15*untested, each 
factor 0..1 (fanout = downstream count / largest fanout; criticality low 
0, medium 0.5, high 1).- Report fields: changeId, change, analysisMs, affected [{nodeId, layer, 
severity, risk, evidence, confidence, checkThis, wave?}], 
businessProcesses [{nodeId, name, owner}], waves [{wave, nodeIds, 
agentCount}] (topological, upstream first), approvals [{nodeId, reason: 
"database"|"pii"}], grep {term, foundNodeIds, missed [{nodeId, reason: 
"alias_chain"|"dynamic_sql"|"cross_language"|"no_literal_reference"}]}.
