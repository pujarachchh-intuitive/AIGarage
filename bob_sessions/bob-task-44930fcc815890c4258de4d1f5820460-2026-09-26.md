## SystemDNA — AWS Deployment Plan

The project has two deployable surfaces:

| Surface | Stack | Target AWS service |
|---|---|---|
| **Frontend** | Next.js 16 (SSR + API routes) | EC2 (Node process) or App Runner / ECS Fargate |
| **Engine backend** | FastAPI + Neo4j + ChromaDB + Redis + MCP, Docker Compose | EC2 `t3.xlarge` |

Because the Next.js app has **server-side API routes** (see [`app/api/`](systemdna/web/app/)) and spawns the `bob` CLI process, it cannot be a pure static export to S3. It must run as a Node server.

### Phase 0 — Prerequisites (local machine, ~30 min)

**Tools to verify:**
```bash
aws --version          # AWS CLI v2
docker --version
docker compose version # v2
node --version         # ≥ 20
git --version
ssh -V
```

**Secrets to collect before touching AWS:**

| Secret | Source |
|---|---|

| `BOB_API_KEY` | IBM Bob Shell |
| `GEMINI_API_KEY` | https://aistudio.google.com |
| `DEMO_TOKEN` | Generate any strong random string, e.g. `sysdt-demo-2026` |

**Create `.env` files locally** (never commit either):
- `systemdna/engine/.env` — see [Phase 0.3 in DEPLOYMENT.md](systemdna/engine/DEPLOYMENT.md:64)
- `systemdna/web/.env.local` — copy from `.env.example` and fill in secrets

### Phase 1 — AWS Account Foundations (~20 min)

**1.1 — Set an AWS Budget alert first (do this before spending a cent):**
```bash
aws budgets create-budget --account-id <ACCOUNT_ID> \
  --budget '{"BudgetName":"systemdna-guard","BudgetLimit":{"Amount":"20","Unit":"USD"},"TimeUnit":"MONTHLY","BudgetType":"COST"}' \
  --notifications-with-subscribers '[{"Notification":{"NotificationType":"ACTUAL","ComparisonOperator":"GREATER_THAN","Threshold":80},"Subscribers":[{"SubscriptionType":"EMAIL","Address":"your@email.com"}]}]'
```

**1.2 — Create the VPC and subnets:**

```
VPC: 10.0.0.0/16  (name: systemdna-vpc)
  Public Subnet A  10.0.1.0/24  (us-east-1a)  — ALB node 1
  Public Subnet B  10.0.2.0/24  (us-east-1b)  — ALB node 2
  Private Subnet   10.0.3.0/24  (us-east-1a)  — EC2 engine host
Internet Gateway attached to the VPC.
NAT Gateway in Public Subnet A (so the private EC2 can reach the internet for git clone, docker pull).
```

**1.3 — Security groups:**

| Group name | Inbound rules |
|---|---|
| `sg-alb` | 443 from 0.0.0.0/0, 80 from 0.0.0.0/0 |
| `sg-ec2-engine` | 22 from your IP only; 8080 + 3000 from `sg-alb` only |
| `sg-ec2-web` | 22 from your IP only; 3000 from `sg-alb` only |

**1.4 — IAM role for EC2 (`systemdna-ec2-role`):**

Attach an inline policy granting:
- `s3:GetObject`, `s3:PutObject`, `s3:ListBucket` on `arn:aws:s3:::systemdna-*`
- `dynamodb:PutItem`, `dynamodb:Query`, `dynamodb:GetItem` on `systemdna-events` table
- `secretsmanager:GetSecretValue` on `arn:aws:secretsmanager:*:*:secret:systemdna/*`
- `logs:CreateLogStream`, `logs:PutLogEvents`
- `ecr:GetAuthorizationToken`, `ecr:BatchGetImage`, `ecr:GetDownloadUrlForLayer`

> **No access keys on disk.** The IAM role grants the instance permissions automatically. Never run `aws configure` on any EC2 host.

**1.5 — ECR repository:**
```bash
aws ecr create-repository --repository-name systemdna-engine --region us-east-1
aws ecr create-repository --repository-name systemdna-web    --region us-east-1
```

**1.6 — AWS Secrets Manager:**
```bash
aws secretsmanager create-secret --name systemdna/gemini  \
  --secret-string "{\"GEMINI_API_KEY\":\"$GEMINI_API_KEY\"}"
aws secretsmanager create-secret --name systemdna/github  \
  --secret-string "{\"GITHUB_TOKEN\":\"$GITHUB_TOKEN\"}"
aws secretsmanager create-secret --name systemdna/bob     \
  --secret-string "{\"BOB_API_KEY\":\"$BOB_API_KEY\"}"
aws secretsmanager create-secret --name systemdna/demo    \
  --secret-string "{\"DEMO_TOKEN\":\"$DEMO_TOKEN\"}"
```

### Phase 3 — EC2: Engine host (FastAPI + Neo4j + Redis + ChromaDB + MCP)

**3.1 — Launch the instance:**
```bash
aws ec2 run-instances \
  --image-id ami-0c02fb55956c7d316 \   # Ubuntu 22.04 LTS, us-east-1
  --instance-type t3.xlarge \           # 4 vCPU, 16 GB — required for Neo4j + agent load
  --key-name your-key-pair \
  --security-group-ids sg-XXXX \        # sg-ec2-engine
  --subnet-id subnet-XXXX \             # private subnet
  --block-device-mappings '[{"DeviceName":"/dev/sda1","Ebs":{"VolumeSize":50,"VolumeType":"gp3"}}]' \
  --iam-instance-profile Name=systemdna-ec2-role \
  --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=systemdna-engine}]'
```

**3.2 — Bootstrap the host** (run [`deploy/bootstrap.sh`](systemdna/engine/deploy/bootstrap.sh)):
```bash
ssh -i your-key.pem ubuntu@<EC2-IP>
sudo bash -c "$(curl -fsSL https://raw.githubusercontent.com/<org>/AIGarage/master/systemdna/engine/deploy/bootstrap.sh)"
# Installs: docker, docker-compose-plugin, git, IBM Bob Shell, clones repo to /app
```

**3.3 — Copy secrets to the host:**
```bash
scp -i your-key.pem systemdna/engine/.env ubuntu@<EC2-IP>:/app/systemdna/engine/.env
```

**3.4 — Sign Bob Shell in (one-time, interactive):**
```bash
ssh -i your-key.pem ubuntu@<EC2-IP>
cd /app && bob login
echo "hello" | bob -p "say hi back" --max-turns 1   # smoke test
```

**3.5 — Start all 6 containers** (from [`docker-compose.yml`](systemdna/engine/docker-compose.yml)):
```bash
cd /app/systemdna/engine
docker compose up -d --build
docker compose ps   # wait for all "healthy" — Neo4j takes ~30 s
```

**Services started:**

| Container | Port (internal) | Role |
|---|---|---|
| `neo4j` | 7474, 7687 | Knowledge graph |
| `chroma` | 8000 | Vector store |
| `redis` | 6379 | LangGraph checkpoints |
| `engine` | — | Scanner / agent workload |
| `api` | **8080** | FastAPI REST + WebSocket |
| `mcp` | **3000** | FastMCP tools for Bob IDE |

> Only ports **8080** and **3000** are reachable from the ALB. Neo4j, Chroma, and Redis are internal-only — never expose them publicly.

### Phase 4 — EC2: Web host (Next.js SSR)

The Next.js app has server-side API routes that spawn the `bob` CLI and call the filesystem — it cannot be deployed as a static site to S3.

**4.1 — Launch a second EC2 instance** (smaller — Next.js is lighter than the engine):
```bash
aws ec2 run-instances \
  --image-id ami-0c02fb55956c7d316 \
  --instance-type t3.medium \           # 2 vCPU, 4 GB — sufficient for Next.js
  --key-name your-key-pair \
  --security-group-ids sg-XXXX \        # sg-ec2-web
  --subnet-id subnet-XXXX \             # private subnet
  --block-device-mappings '[{"DeviceName":"/dev/sda1","Ebs":{"VolumeSize":30,"VolumeType":"gp3"}}]' \
  --iam-instance-profile Name=systemdna-ec2-role \
  --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=systemdna-web}]'
```

**4.2 — Install runtime and start the app:**
```bash
ssh -i your-key.pem ubuntu@<WEB-EC2-IP>

# Install Node 22 + IBM Bob Shell
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt-get install -y nodejs git
curl -fsSL https://bob.ibm.com/download/bobshell.sh | bash
bob login

# Clone repo and install dependencies
git clone https://github.com/<org>/AIGarage.git /app
cd /app/systemdna/web
npm install

# Set environment (point at the engine ALB URL once it's up)
cat > .env.local << 'EOF'
GITHUB_TOKEN=<from-secrets-manager>
BOB_API_KEY=<from-secrets-manager>
NEXT_PUBLIC_API_URL=https://api.your-domain.com
SYSTEMDNA_DATA_DIR=/app/systemdna/web/.data
EOF

# Build and start with PM2 for process management
npm install -g pm2
npm run build
pm2 start "npm start" --name systemdna-web
pm2 save && pm2 startup
```

> Next.js listens on port **3000** on this host (not to be confused with the MCP container on the engine host, which also uses port 3000 but is behind a different target group).

### Phase 5 — Application Load Balancer (ALB)

**5.1 — Create the ALB:**
```bash
aws elbv2 create-load-balancer \
  --name systemdna-alb \
  --subnets subnet-PUBLIC-A subnet-PUBLIC-B \
  --security-groups sg-alb \
  --scheme internet-facing \
  --type application
```

**5.2 — Request an ACM certificate** (HTTPS):
```bash
aws acm request-certificate \
  --domain-name your-domain.com \
  --subject-alternative-names "*.your-domain.com" \
  --validation-method DNS
# Add the CNAME record it gives you to your DNS provider, then wait for "Issued"
```

**5.3 — Create target groups:**

| Target group | Protocol | Port | Instance |
|---|---|---|---|
| `tg-web` | HTTP | 3000 | `systemdna-web` |
| `tg-api` | HTTP | 8080 | `systemdna-engine` |
| `tg-mcp` | HTTP | 3000 | `systemdna-engine` |

**5.4 — ALB listener rules (HTTPS :443):**

| Path pattern | Forward to |
|---|---|
| `/api/engine/*` | `tg-api` |
| `/ws` | `tg-api` (WebSocket) |
| `/mcp/*` | `tg-mcp` |
| `/*` (default) | `tg-web` |

**5.5 — Critical WebSocket setting** (Bob agent runs last minutes):
```bash
aws elbv2 modify-load-balancer-attributes \
  --load-balancer-arn arn:aws:elasticloadbalancing:... \
  --attributes Key=idle_timeout.timeout_seconds,Value=3600
```

**5.6 — HTTP → HTTPS redirect on :80:**
```bash
aws elbv2 create-listener \
  --load-balancer-arn <ALB-ARN> \
  --protocol HTTP --port 80 \
  --default-actions Type=redirect,RedirectConfig='{Protocol=HTTPS,StatusCode=HTTP_301}'
```

### Phase 6 — CloudWatch Logging

```bash
# Create one log group per container
for svc in api mcp engine neo4j redis chroma web; do
  aws logs create-log-group --log-group-name /systemdna/$svc
done
```

Add `awslogs` log driver to [`docker-compose.yml`](systemdna/engine/docker-compose.yml) for the `api` and `mcp` services (the ones externally reachable), pointing at `/systemdna/api` and `/systemdna/mcp`.

### Phase 7 — CI/CD Pipeline (GitHub Actions)

Three jobs, in this order:

**7.1 — Secret scan (build this first — IBM disables accounts that leak API keys):**
```yaml
# .github/workflows/secret-scan.yml
- uses: gitleaks/gitleaks-action@v2
  env:
    GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

**7.2 — Build, test, push to ECR, deploy to EC2:**

GitHub Actions secrets to set: `AWS_REGION`, `ECR_REPO_ENGINE`, `ECR_REPO_WEB`, `EC2_ENGINE_HOST`, `EC2_WEB_HOST`, `EC2_SSH_KEY`

The existing [`deploy/deploy.sh`](systemdna/engine/deploy/) script handles: `docker build → aws ecr login → docker push → ssh pull + compose up`.

**7.3 — Frontend deploy step:**
```bash
cd systemdna/web
npm install && npm run build
# SSH into web EC2, git pull, npm run build, pm2 restart
```

### Phase 8 — Smoke Tests

Run after Phase 5 ALB is live. Every line must pass before considering it deployed.

```bash
# 1. API health
curl -s https://your-domain.com/api/engine/health
# → {"status":"ok"}

# 2. WebSocket stays connected for > 60 s (validates the 3600 s timeout)
wscat -c wss://your-domain.com/ws
# → stays open; type anything; no disconnect

# 3. Impact analysis round-trip
curl -s -X POST https://your-domain.com/api/engine/changes \
  -H "Authorization: Bearer $DEMO_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"node":"db:column:orders.cust_id","change":"rename","to":"customer_id"}'
# → JSON with change_id and report

# 4. Frontend loads and reaches live mode (not simulator)
# Open browser → https://your-domain.com
# Settings page must show Bob as "ready" (green)
# Agent City map must show real nodes, not the demo ShopFlow simulator

# 5. Permit hook blocks out-of-scope edits
echo '{"event":"PreToolUse","tool":"write_to_file","tool_input":{"path":"backend/routes.py"}}' \
  | SYSTEMDNA_AGENT_ID=fix-stg-orders python systemdna/engine/hooks/permit_check.py
echo $?   # must print 2 (BLOCKED)
```

### Phase 9 — Tear Down After the Demo

```bash
# Stop containers on engine EC2
ssh -i your-key.pem ubuntu@<ENGINE-IP> \
  "cd /app/systemdna/engine && docker compose down -v"

# Stop Next.js on web EC2
ssh -i your-key.pem ubuntu@<WEB-IP> "pm2 stop systemdna-web"

# Delete all AWS resources (avoids surprise bills)
aws ec2 terminate-instances --instance-ids <ENGINE-ID> <WEB-ID>
aws elbv2 delete-load-balancer --load-balancer-arn <ALB-ARN>
aws s3 rm s3://systemdna-artifacts --recursive && aws s3api delete-bucket --bucket systemdna-artifacts
aws dynamodb delete-table --table-name systemdna-events
for secret in systemdna/gemini systemdna/github systemdna/bob systemdna/demo; do
  aws secretsmanager delete-secret --secret-id $secret --force-delete-without-recovery
done
```

### What is not built yet (blockers before a full live demo)

Per [`systemdna/STATUS.md`](systemdna/STATUS.md) and the existing [`DEPLOYMENT.md`](systemdna/engine/DEPLOYMENT.md):

| Missing piece | Impact on deployment |
|---|---|
| Python scanners (`python_scan.py`, `sql_scan.py`) | Engine API returns an empty graph; city renders zero buildings |
| Orchestrator waves (`orchestrator.py`) | Agent runs are simulated, not real |
| ShopFlow sample repo | Scanner has nothing to scan on first boot |
| AWS infra (VPC, ALB) | No public URL — phases above fill this gap |
| Bob custom modes (`.bob/modes/`) | Bob IDE can't drive changes from the IDE |

The deployment infrastructure in phases 0–9 above can be stood up fully today. The agent-run features will become real as those Python components are built in parallel.
